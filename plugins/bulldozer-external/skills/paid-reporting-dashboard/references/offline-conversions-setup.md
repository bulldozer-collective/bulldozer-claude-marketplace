# Offline Conversions Setup and Validation

**Google Ads offline conversion setup:**
1. Create conversion actions in Google Ads: one per CRM milestone (`MQL`, `SQL`, `Opportunity`, `Closed-Won`)
2. Assign conversion values reflecting deal economics:
   - MQL: €50 (low signal)
   - SQL: €200
   - Opportunity: €500
   - Closed-Won: actual deal value (or ACV estimate)
3. Connect via HubSpot/Salesforce's native Google Ads integration — this is the path to default to. Google deprecated the legacy `UploadClickConversions` API import on June 15, 2026: an account that wasn't already calling it between December 2025 and May 2026 now hits a hard `CUSTOMER_NOT_ALLOWLISTED_FOR_THIS_FEATURE` error on first use, and the replacement is the Data Manager API. That cutoff is specifically about custom-built integrations calling the old API directly — the standard CRM connectors (HubSpot, Salesforce) run underneath it and are themselves migrating to Data Manager, so the native integration keeps working without the client needing to touch this. Only relevant if you're tempted to build a custom import instead of using the native connector: don't, unless the account already had that legacy call running before the cutoff.
4. Switch bidding to Target ROAS or Maximize Conversion Value once you have 30+ offline conversions/month

**If the account is managed directly through Bulldozer OS rather than through the CRM's native connector,** the OS exposes this same click-upload path natively: `bdzCreateSeaConversionAction(accountId, name, type=UPLOAD_CLICKS)` creates the conversion action (the tool's default type, `WEBPAGE`, is for on-site tags and is rejected here — `type` must be set explicitly), then `bdzUploadSeaConversions(accountId, conversionActionId, conversions=[{gclid, conversionDateTime, conversionValue, ...}])` sends the batch. Check `bdzGetSeaAutoTagging(accountId)` first — without auto-tagging the clicks never carried a `gclid` to upload against. This is the *same* Google-side path described above, not a way around its restriction: it is gated by the same June 15, 2026 cutoff for new adopters, and Google has since named a harder deadline on top of it — full shutdown of this click-upload path in March 2027, even for accounts that kept legacy access past the first cutoff. Treat it as a bridge with an expiration date, not a long-term architecture. One trap that applies regardless of which path calls it: a 200 response does not mean every row landed — Google runs the batch in partial-failure mode, so read the per-row `results` field (accepted / error per conversion) rather than trusting the status code alone. **A free enrichment worth adding while you're building this call:** pass `email` and/or `phoneNumber` on each conversion row alongside the `gclid` and it becomes an Enhanced Conversion on top of the click upload — Google treats the two as one and the same submission. The click identifier is still mandatory either way (only it and `conversionDateTime` are required), so this isn't the GCLID-free "Enhanced Conversions for Leads" variant; it's a match-rate booster layered onto the path you're already calling. Send both fields in clear text — the server hashes them (SHA-256 of the normalized value) itself and never stores or logs the raw value. Do not pre-hash: Google's Gmail-specific normalization rule is easy to get wrong, and a mismatched hash fails to match with no error to surface it.

**LinkedIn Ads offline conversion setup:**
1. In Campaign Manager → Conversions → Create Conversion
2. Select "Lead Gen Form" or "Website" conversion type → add CRM stage triggers via LinkedIn integration or manual CSV upload
3. Attribution window: post-click conversions default to 30 days and view-through to 7 — both are adjustable independently to 1/7/30/90 days in the conversion action's settings. LinkedIn's own guidance recommends 90 days on **both** for most conversion types, not just a post-click bump: an account that raises post-click to 90 and leaves view-through at its 7-day default is still undercounting view-through credit on a long B2B cycle. Five conversion categories that map directly onto this skill's funnel — Lead, Qualified Lead, Submit Application, Purchase, Add to Cart — go further still, up to a 365-day window, but only when the conversion is reported via the Conversions API or a CSV upload; it isn't a setting exposed in the Campaign Manager UI. (Direct read of linkedin.com and learn.microsoft.com still blocked at egress this pass, same as every prior attempt — but a web search surfaced what reads as a direct quote of Microsoft's own LinkedIn Marketing API reference, naming the same five categories by their API enum values — `SUBMIT_APPLICATION`, `PURCHASE`, `ADD_TO_CART`, `QUALIFIED_LEAD`, `LEAD` — and the same 30-day/7-day post-click/view-through defaults already stated above, as named parameters (`postClickAttributionWindowSize` default 30, `viewThroughAttributionWindowSize` default 7). That's a stronger match than the earlier secondary-source convergence — it's the primary document's own parameter names, not a blog's paraphrase — but it's still a search-engine extract, not a fetched page: re-verify by direct fetch before this figure goes in front of a client as a guaranteed platform ceiling.)
4. **Link the rule to the campaign — creating it in Campaign Manager is not enough.** Bulldozer OS has no tool to create a LinkedIn conversion rule (that step stays in Campaign Manager), but it does read the rules that already exist: `bdzListAdLinkedInConversions(adAccountId)` returns each rule's `originId`. A campaign with objective `AD_OBJECTIVE_WEBSITE_CONVERSIONS` only measures and optimises against a rule once that `originId` is passed in `linkedIn.conversionIds` on `bdzCreateAdLayer2` or `bdzUpdateAdLayer2` — skip this and the campaign serves normally and reports normally on every other metric, with nothing (no error, no 400) flagging that it credits zero conversions. If the ad account is managed outside Bulldozer, the equivalent step is confirming the conversion action is actually attached to the campaign in Campaign Manager, not just present in the account's conversion list. A rule with `enabled: false` has been deleted on LinkedIn's side — drop it from `conversionIds` rather than leaving a dead reference in place.

**Validation:** After 30 days, verify that offline conversions are appearing in Google Ads campaign performance. If import shows 0 conversions everywhere on the account, check `bdzGetSeaAutoTagging(accountId)` first — it reads the auto-tagging switch live from Google, and that switch is account-wide, never per-campaign. That makes it the right first check only when *every* campaign on the account shows zero. If some campaigns show conversions and others don't, auto-tagging isn't the cause (there's no per-campaign variant of it to be half-broken) — look instead at a tracking template overridden at the campaign or ad level, a disabled final URL suffix, or a landing page stripping query parameters on just those campaigns' pages. If the ad account is registered in Bulldozer, you don't need the platform UI to check any of this — pulling campaign-level ad analytics for that account (`bdzGetAdAnalytics`) returns cost, conversions and cost-per-conversion directly, including whatever offline conversions have landed — pass `from`/`to` explicitly on this check (e.g. the last 30–45 days): the tool defaults to a 180-day lookback when they're omitted, and an unqualified pull blends six months of history into one number, which defeats a check whose entire point is "did the last 30 days work." Read the response's `freshness` entry for the account before concluding anything from a 0-conversion read: these numbers are only as current as the last successful import, and an account where `upToDate` is `false` is reporting through `dataThrough`, not through today — a stalled import (token expired or missing, per `lastAttemptErrorKind`) produces the same flat "0 conversions" picture as a genuinely broken offline-conversion chain, and no amount of GCLID or `conversionIds` debugging fixes that. One Meta-specific trap if that platform is in the mix: its `conversions` field counts only terminal events (purchase, lead, and equivalents); the upper-funnel breakdown reported alongside it (`conversionsPerType`) overlaps with that count and must never be added on top when recomputing a cost-per-SQL — and a third bucket, `custom_pixel_events` (an unnamed aggregate the tool falls back to when it can't resolve individual custom pixel event names), is excluded from `conversions` for the same reason and must be read as-is, never summed in. **On LinkedIn specifically, if a `WEBSITE_CONVERSIONS` campaign shows zero conversions despite a correctly firing Insight Tag,** check the campaign/ad-group's `conversionIds` before suspecting the tag: a missing or mismatched link produces exactly this symptom, with no error anywhere in the setup flow to point at it.
