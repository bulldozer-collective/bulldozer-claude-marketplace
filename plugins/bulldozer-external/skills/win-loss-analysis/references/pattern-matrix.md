# Pattern Extraction — Detail

**Don't tag "Price" at face value — probe once more before you accept it.** Win-loss research vendors with large interview datasets (Primary Intelligence, Clozd — vendor-published figures, not an independent analyst study, but consistent with the buyer-only principle this whole program runs on) report that reps attribute losses to price roughly twice as often as buyers actually confirm it as the deciding factor. Before tagging an interview "Price," ask one more question: *"If price hadn't been a concern, what would you have chosen?"* or *"If we'd been free, would you have picked us?"* — a buyer who still names the competitor is telling you it was never really about price. What's left after that probe splits two ways: an absolute budget ceiling tags as Price; a complaint about value relative to the alternative belongs in Message (they didn't buy your ROI case) or Process (they never got the pricing conversation they needed), not Price.

**At 10+ interviews, build the pattern matrix — one matrix per segment, never pooled.** Deal-size bands, `dealtype`, and, where they exist, separate pipelines or product lines all run on different buying dynamics — the same discipline this skill already applies in `## Input` applies to pattern-matching too. Use whatever granularity `dealtype` actually has on the connected portal: a plain New Business / Existing Business split at minimum, or the portal's own custom values (Renewal, Upsell) if it has extended the field — don't collapse renewal and upsell losses into one "Existing Business" row when the portal already tells them apart. Pooling enterprise and SMB interviews in one matrix buries a segment-specific competitive threat under a larger, unrelated sample; pooling new-logo losses with renewal/expansion losses does something worse — it can average a real competitive threat against a retention problem that has nothing to do with a competitor at all. Run the 3+ mentions threshold separately per segment before calling anything company-wide:
- Which loss reason appears 3+ times **within a segment**? → Systematic finding for that segment
- Which competitor appears 3+ times in losses **within a segment**? → Build or update battlecard, scoped to that segment
- Where deals stall consistently? → Sales process problem, not competitive problem
- What's praised consistently? → Don't change this — protect it
