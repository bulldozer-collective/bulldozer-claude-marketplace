Six rows, not one per finding — a scorecard that grows a row every time a new driver shows up stops getting read. "Top win/loss drivers" holds a ranked list (1–2 items, the ones clearing the 3+ mentions threshold that month), not a running table of every driver ever found.

### Reading the Scorecard, Not Just Filling It In

A scorecard nobody acts on is decoration. Three rules for using it:

- **"Win rate (interviewed sample)" is not your company's overall win rate.** It's the win rate inside the interviewed sample only — state the sample size and segment next to the number every month. A win rate computed on 6 interviews is a signal, not a statistic, and it should never be quoted outside the program without that caveat. Below 5 interviews in a given month, don't publish a percentage at all — show the raw count ("3 of 4 interviewed") instead of a rate that implies more precision than the sample supports.
- **A driver only earns a Trend arrow after two consecutive months of the same signal.** One good or bad month is noise. Apply the same 3+ mentions threshold from Pattern Extraction before calling a month-over-month shift real — don't let a single interview move the arrow.
- **"Interventions fielded" counts actions taken against a prior finding, not the count of findings.** A month with five new findings and zero interventions means the program produced a report, not a change — that's the number leadership should ask about, not the win rate.

**Close the loop every month before adding a new finding.** Check the finding from two months back: did the intervention move the metric it was meant to move? If a loss driver marked "intervention: shipped" reappears at the same rate the following month, the fix didn't work — reopen that finding under its original owner. Don't file a fresh finding next to it; that hides the fact that the first fix failed.
