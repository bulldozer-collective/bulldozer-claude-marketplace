# SEO Objects

## SEO Domain
A `SeoDomain` represents the logical link between a `Company` and a web domain.
To get a company's domain(s), use `mcp__plugin_bulldozer_bulldozer__getSeoDomains` with the `companyId` parameter.

## SEO Analysis
A `SeoAnalysis` represents the high-level operation to fetch SEO data for a `SeoDomain`.
A `SeoAnalysis` is asynchronous — once started, its status must be polled until completion.
A `SeoAnalysis` is scoped by:
- A `SeoDomain`
- A month/year tuple
- A source (country, optionally device-qualified — see "SEO Data Sources" below)

## SEO Domain Overview
A `SeoDomainOverview` contains the usual SEO data for a `SeoDomain`:
- The rank
- The organic traffic
- The branded traffic percent
- The organic keyword count
- The organic cost

## SEO Backlink Overview
A `SeoBacklinkOverview` contains:
- The total number of backlinks
- The authority score
- The number of referring domains
- The number of follow links
- The number of nofollow links

## SEO Keyword
A `SeoKeyword` contains:
- The keyword
- A branded flag
- The position
- The URL
- The volume
- The CPC
- The difficulty
- A list of intents
- The number of results
- The trends
- The traffic percent generated by this keyword
- The traffic cost percent generated by this keyword

# SEO Operations

## Step 1 — Resolve the Company ID
To resolve a `companyId` from a user-provided website or company name, call `mcp__plugin_bulldozer_bulldozer__listCompanies` and match against the user's input.
- If matching is ambiguous, **prompt the user** to confirm which company to use.
- The `companyId` is critical — there must not be any doubt before proceeding.

## Step 2 — Resolve the Source (Country + Device)
SEO data is always tied to a source (see "SEO Data Sources"). Before fetching:
- If the user specified a country, use it.
- Otherwise, infer from the company's primary market if obvious, or **ask the user** which country to target.
- For every base country source, you must **also** fetch the corresponding `MOBILE_${country}` source and merge the results (see "Merging Desktop and Mobile").

## Step 3 — Resolve the Month/Year
- The current month is **never available**. Do not create analyses or fetch data for the current month.
- If the user did not specify, default to the most recently completed month.

## Step 4 — Unified Workflow to Get SEO Data
Execute these steps in order:

1. Call `getSeoDomains` with `companyId`. If no `SeoDomain` exists for the target domain, call `createSeoDomain` to create it.
2. Attempt to fetch the desired data (`getSeoDomainOverview`, `getSeoDomainKeywords`, or `getSeoBacklinksOverview`) for the (domain, month, year, source) tuple.
3. If data is not available for that tuple, call `createSeoAnalysis` for it.
4. Poll the analysis using the polling protocol below until it is `COMPLETED` (or fail).
5. Re-fetch the data after the analysis completes.
6. Repeat steps 2–5 for the `MOBILE_${country}` source.
7. Merge the desktop and mobile results (see below) before presenting to the user.

## Polling Protocol
Use `mcp__plugin_bulldozer_bulldozer__getSeoAnalysis` to poll the analysis status.
- **Expected statuses:** `PENDING`, `RUNNING`, `COMPLETED`, `FAILED` (treat any unknown non-terminal status as still running).
- **Interval:** wait ~10 seconds between polls.
- **Timeout:** stop polling after roughly 20 attempts (~3–4 minutes). If still not terminal, report a timeout to the user and stop — do not silently retry forever.
- **On `COMPLETED`:** proceed to fetch the data.
- **On `FAILED`:** report the failure (and any error detail returned) to the user and stop. Do not automatically recreate the analysis.

## Merging Desktop and Mobile Results
When combining a base country source (e.g. `US`) with its mobile counterpart (`MOBILE_US`):
- **Domain overview numeric metrics** (organic traffic, organic keyword count, organic cost, total backlinks, etc.): **sum** the two values.
- **Rank, authority score, percentages** (branded traffic %, traffic %, traffic cost %): present **both values side by side** (desktop and mobile) — do not average, since they are not directly additive.
- **Keyword lists:** **deduplicate by keyword string**. When the same keyword appears in both sources, prefer the entry with the better (lower-numbered) position and annotate that it appears on both devices. Keep volume/CPC/difficulty from whichever source has them populated; if both, prefer the base country source.
- Always disclose to the user that the reported figures combine desktop and mobile sources.

# SEO Data Sources
SEO data is fetched from a source (also called a database). A source is always linked to at least a country (e.g. `US`, `FR`). It may also be device-qualified, e.g. `MOBILE_US`.

**Rule:** whenever you fetch from a country source, also fetch from `MOBILE_${country}` and merge the results as described above.

# Tool Parameters
For exact parameter names, types, and required fields, defer to each tool's own schema. The key dimensions you will typically need to provide are:
- `companyId` — for `listCompanies` follow-ups, `getSeoDomains`, `createSeoDomain`.
- `seoDomainId` (or domain URL on creation) — for analysis and data tools.
- `month`, `year` — for any analysis or data fetch.
- `source` — the country (and optionally the `MOBILE_${country}` variant).

If a required parameter is missing from the user's request and cannot be safely defaulted, ask the user.

# Worked Example
**User:** "Show me the SEO performance of acme.com for last month in the US."

1. Call `listCompanies`, find the entry matching "acme.com". If multiple match, ask the user to confirm. → obtain `companyId`.
2. Determine month/year = previous calendar month. Country = `US`. Sources to query: `US` and `MOBILE_US`.
3. Call `getSeoDomains(companyId)`. If no domain for acme.com, call `createSeoDomain(companyId, "acme.com")`.
4. Try `getSeoDomainOverview` for (domain, month, year, `US`).
   - If unavailable: call `createSeoAnalysis(...)`, then poll `getSeoAnalysis` every ~10s up to ~20 times until `COMPLETED`. Re-fetch.
5. Repeat step 4 for source `MOBILE_US`.
6. Merge the two overviews per the merging rules.
7. Present the consolidated results to the user, noting that figures combine desktop and mobile.
