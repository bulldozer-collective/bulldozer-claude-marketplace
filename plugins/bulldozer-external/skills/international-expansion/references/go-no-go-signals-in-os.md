# Checking the Go/No-Go Signals in Bulldozer OS

### Checking These Signals in Bulldozer OS

Two of the six signals above have a real data source in Bulldozer OS instead of a guess:

- **Inbound demand / organic customer presence** — `bdzGetSeoDomains` lists every SEO domain already tracked on the project; `domain` is an optional filter, not a required one — omit it to see the full list and check whether the company's own domain is already there (confirmed by a real call: omitting both filters returns every tracked domain, no error). If it is, don't read `bdzGetSeoDomainOverview` blind: its `sources` filter only returns data for markets the domain was actually configured to analyze — a market missing from that domain's `sources` comes back empty, not zero, and plenty of real domains sit with `sources: []` (nothing configured yet). Add the target market to the domain first with `bdzUpdateSeoDomain` if it isn't already listed, then read the overview. Registering a brand-new domain (`bdzCreateSeoDomain`) **silently defaults to `sources: [FRANCE]`** when the parameter is omitted — always pass the client's real target market explicitly, whatever it is, never rely on that default. Each market declared this way (new or existing domain) costs one paid provider call per monthly analysis, so declare the market under real consideration, not every country on a long list — and note China has no matching value in this catalog (`bdzListSeoDataSources`), so it stays a manual, external read rather than something this tool can size.
- **A sharper cut on the same signal, if Google Analytics is connected** — the SEO overview above tells you whether the country is *searching* for the product; it doesn't tell you what happens once someone from that country actually lands on the site. `bdzListGoogleAnalyticsDimensions` carries a `country` dimension (confirmed by a real call — `Geo` use-case, alongside `city`), which a report template (`bdzCreateGoogleAnalyticsReportTemplate`) can cross with a conversion metric to read actual signups or conversions per country — a behavioral read, not a visibility proxy. Run both where you can: strong SEO visibility from a country paired with weak GA4 conversion from it means people are finding the product and bouncing, a different problem than nobody finding it at all.
- **Formal tracking of the decision** — expect this to be a feature you're getting the client to adopt, not data that's already there: a sample of 15 real client projects (plus Bulldozer's own internal project) all came back with zero declared markets. Check first with `bdzListProjectMarkets` (a 404 with an empty body means none declared yet, not a broken call) rather than assuming either way. Once the Go/No-Go framework returns a "go" and you move into Phase 3, declare the market with `bdzCreateProjectMarket` (ISO country code + free-form `properties`, no key validation) rather than leaving the decision to live only inside the `expansion-brief-{market}.md` file — it's what downstream project analyses key off, and it's how a client's Bulldozer workspace actually knows which countries are in play, once someone actually uses it. Don't default to the tool schema's own example key (`segment: mid-market`): the one market actually declared anywhere in the sample — Bulldozer's own internal project — carries `geoLocId` instead, a Google Ads/Analytics geo-targeting ID, and no `segment` at all. That's still a single observed case, not a confirmed convention, but if the Phase 3 plan depends on geo-targeted media execution downstream, confirm what key the client's ad tooling actually expects before leaning on the schema's example. Both calls also require a third identifier, `targetProjectId`, alongside the usual `customerId`/`projectId` — it isn't optional, omitting it fails the call before it reaches the "none declared yet" 404 above.

The other four signals (competitor presence, regulatory risk, language barrier, infrastructure readiness) stay judgment calls informed by the research in this brief — Bulldozer OS has no tool that scores them.
