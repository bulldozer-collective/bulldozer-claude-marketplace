# Bulldozer OS Data and Analyses Used by This Audit

## Step 1 — Getting deal data from the CRM connector

**Bulldozer OS does not hold deal stage or closed-won/lost data itself — that lives in the client's CRM.** If a CRM connector is live for this client (HubSpot is the one wired into this environment today), query the deal object directly instead of asking someone for a manual export: read the deal stage, close date, and whatever property carries the lost reason. Don't guess the property name — confirm it against the connector's own schema tool before querying. If no CRM connector is connected, fall back to whatever export the client can hand over, or the manual pull described above.

## Step 2 — Stored ICP profiles in Bulldozer OS

**If this client's project is set up in Bulldozer OS, start from its stored ICP profiles rather than asking for the document from scratch.** The OS keeps a typed set: declared ICPs, anti-personas (who to actively decline), prescribers (who recommends the company without buying), and blind spots (segments the offer already fits but the company doesn't talk about). A blind-spot profile is a specific kind of finding for this audit: a segment the positioning ignores even though nothing about the offer excludes it. But treat this as the *declared* ICP, not the revenue-grounded one — it still has to be checked against the actual revenue cut above, never substituted for it.

## Step 3 — Existing value proposition analysis in Bulldozer OS

**If Bulldozer OS already has a value proposition analysis for this project, pressure-test that instead of re-transcribing claims off the site by hand.** It returns each claimed value proposition — marked primary or secondary — with its own proof point, plus a separate list of claimed differentiators. Run the three checks against each one individually: a "secondary" value prop that fails all three checks is a lower-priority fix than a "primary" one that fails them.

## Step 5 — Project-level analyses already running in Bulldozer OS

**If this client's project is set up in Bulldozer OS, most of this step is already running as a project-level analysis — check before rebuilding it by hand:**
- A market-perception analysis, when it has completed, gives the Perception Gap Analysis this audit's output already asks for: an outside read of the brand's image, whether each claimed value proposition is independently confirmed anywhere (or exists only on the company's own site), sourced positive and negative external signals, and named "silence zones" — topics or comparisons the market never makes despite an active category around it. A silence zone is itself a finding.
- A market-positioning analysis, when complete, gives a two-axis whitespace map with each competitor placed and a one-line justification for the placement, plus its own summary note on where the defensible quadrant sits. Use it as the starting whitespace map rather than inventing axes.
- A competition-intensity analysis, when complete, scores each tracked competitor on a channel-by-channel strength basis (SEO, paid search, CRO, GEO, Meta, LinkedIn, organic social) alongside an estimated monthly media budget — this is what turns the logo-swap test from an eyeball exercise into a claim you can defend with a number per channel.
- **Market-perception and market-positioning don't return their text fields as plain strings — each is wrapped as `{value, override, overridden}`**: market-perception wraps `perceivedImage`, `spontaneousPositioning`, and `note` directly. Market-positioning wraps its own `note` the same way, but `axisX` and `axisY` are *not* themselves wrapped — each is a container with three sub-fields, `label`, `lowLabel`, `highLabel`, and it's those three sub-fields, individually, that come back as `{value, override, overridden}`. Check `overridden` sub-field by sub-field (`axisX.label`, `axisX.lowLabel`, `axisX.highLabel`, same for `axisY`) before quoting any of them in the Perception Gap Analysis or the Competitive Positioning Map — `value` is the AI's first draft, `override` the client's confirmed correction, and a single check at the whole-axis level reads a field that doesn't exist, which silently falls back to the AI's draft everywhere the client actually corrected it.
- These are async jobs (state RUNNING / SUCCESS / ERROR) — judge freshness from when the run *started*, not when the record was first created, since re-runs reuse the same record. A run stuck in RUNNING auto-fails to ERROR after 60 minutes, so a stale RUNNING state is never a permanent block — re-trigger it rather than waiting indefinitely or assuming the tool is broken. Re-triggering market-positioning while a run is still in progress returns a conflict naming that run's start time, not a second run; it isn't a lock either, just retry once the 60-minute auto-fail has passed. If a job is still running, errored, or was never triggered for this project, say so and fall back to the manual method below rather than stalling the audit on it.
- **The market-positioning analysis has a prerequisite chain — an ERROR or never-triggered state here isn't automatically a tooling problem.** It can only run once the value-proposition analysis *and* the market-perception analysis are themselves already complete, plus at least one competitor tracked on the project; missing any of the three fails the run outright. Before treating a missing or failed positioning map as something to flag to the client's ops team, check that its two prerequisite analyses are both complete and that a competitor is actually being tracked — the map not existing is often just those steps not having been done yet, not a broken analysis.
- Competitors already tracked for the project link to company records that can carry Trustpilot and Google Business Profile reviews, and logged public ad creatives (platform, targeting, impression range, active dates) — pull those for the vulnerability scan and the logo-swap test instead of manual screenshots. Tracked-review coverage stops at Trustpilot and Google Business Profile: G2 and Reddit still require an ad hoc web search, and that call is credit-metered — scope it to the one or two competitors the audit actually turns on, not the full list by default.

## Step 6 — Tone-of-voice configuration in Bulldozer OS

**If Bulldozer OS holds a tone-of-voice configuration for this project, use it as the reference to check touchpoints against** — it defines the intended tones, keywords, and, most usefully here, an explicit anti-keywords list: language the brand has decided never to use. Any touchpoint using an anti-keyword is an automatic consistency fail, no judgment call needed.
